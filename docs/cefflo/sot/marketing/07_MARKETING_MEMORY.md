# CEFFLO MARKETING MEMORY — CANONICAL LEARNING SOT
**Version:** 1.0 — 2026-09-04
**Status:** Schema initialized; performance memory starts empty until real evidence is collected.
**Purpose:** Preserve what the market actually teaches Cefflo and make that evidence reusable by the AI Marketing Engine.

## 1. Critical Rule
Marketing Memory is **not invented knowledge**.

At initialization:
- no winning hook is assumed;
- no winning audience is assumed;
- no winning format is assumed;
- no testimonial is assumed;
- no performance benchmark is assumed.

Only observed evidence may become performance memory.

## 2. Engine Hierarchy
**Founder → n8n Orchestrator**

Knowledge feeding execution:
- Product Truth;
- Brand Brain;
- Marketing Memory.

AI Factory:
1. Content & Strategy
2. Creative Production Router
3. Product Truth + QA
4. Publishing
5. Analytics & Learning
6. Weekly Winner Engine
7. Paid Growth

Canonical loop:
**CREATE → TEST ORGANIC → MEASURE → SELECT TOP 5 → PAID AMPLIFICATION → LEARN → CREATE BETTER**

## 3. Current Experiment Volume Doctrine
Target:
**5 core experiments/day → ~35/week**

Each core experiment may create platform-native derivatives for TikTok, Instagram, Facebook and Threads.

Theoretical ceiling:
**~140 platform outputs/week**

140 is not a quota. Do not publish weak or inappropriate derivatives merely to hit volume.

Note: any older Content Engine rule specifying 3/day or 21/week is superseded for this Marketing Engine by the Founder-approved 5/day model.

## 4. What Marketing Memory Stores
### A. Experiment Memory
- experiment_id;
- objective;
- audience hypothesis;
- pain point;
- angle;
- hook;
- core message;
- proof used;
- CTA;
- format;
- platform plan;
- date/version.

### B. Asset Memory
- asset_id;
- parent experiment;
- production lane/provider;
- creative treatment;
- duration/aspect ratio;
- script/copy version;
- QA result;
- production cost.

### C. Publication Memory
- platform;
- post ID;
- publish time;
- caption/copy;
- derivative lineage;
- status;
- attribution/UTM where available.

### D. Performance Memory
Preserve raw metrics and timestamps, including available:
- impressions/reach;
- views;
- watch time;
- retention/completion;
- likes;
- comments;
- shares;
- saves;
- profile actions;
- clicks;
- landing sessions;
- leads;
- signup/early-access/demo intent;
- conversion;
- paid metrics.

### E. Qualitative Memory
- comment themes;
- objections;
- repeated questions;
- confusion;
- positive language;
- audience wording;
- unexpected use cases;
- sales/Founder observations.

### F. Learning Memory
Each learning records:
- learning_id;
- period;
- hypothesis;
- evidence;
- sample size/context;
- confidence;
- what appears to work/not work;
- recommended next experiment;
- expiry/review date where relevant.

### G. Paid Memory
- source organic experiment;
- campaign/ad/ad-set IDs;
- audience;
- objective;
- spend;
- creative;
- results;
- stop/scale decision;
- paid-vs-organic learning.

### H. Cost Memory
Track production/model/tool/ad costs by experiment and period.

## 5. Experiment Identity

- `E014-TT01`
- `E014-IGR01`

Every derivative must retain its parent lineage.

## 6. Memory Taxonomy
Tag experiments by:
- audience;
- business type;
- operational pain;
- funnel stage;
- content pillar;
- angle;
- hook type;
- proof type;
- format;
- platform;
- CTA;
- product capability referenced.

Taxonomy should be controlled enough for comparison but extensible as real patterns emerge.

## 7. Funnel Memory
Track movement through:
**Unaware → Problem-aware → Cefflo-aware → Trust → Intent → Trial/Early Access → Use → Proof → Referral**

Do not judge every content item by direct conversion. Its objective must be known before scoring.

## 8. Winner Doctrine
Weekly Winner Engine selects approximately Top 5 based on evidence.

Views alone do not define a winner.

Consider:
- retention;
- completion;
- qualified engagement;
- saves/shares;
- meaningful comments;
- profile actions;
- qualified traffic;
- leads;
- conversion;
- strategic relevance;
- paid efficiency when applicable.

Winner weights must remain configurable.

Always preserve raw metrics so historical scores can be recalculated when the scoring model changes.

## 9. Winner Types
Do not store only "winning posts."

Extract separate learnings for:
- winning problem;
- winning audience;
- winning angle;
- winning hook;
- winning format;
- winning proof;
- winning CTA;
- winning platform execution;
- winning creative pattern.

A viral asset may be a weak business winner. A modest-reach asset may be a strong qualified-lead winner.

## 10. Losing Content
Losers are valuable evidence.

Record:
- hypothesis;
- execution;
- distribution;
- metric weakness;
- likely explanation;
- confidence;
- whether to kill, retry or change one variable.

Do not repeatedly regenerate a failed angle without recording why a new test is materially different.

## 11. Confidence Levels
Use:
- **OBSERVATION** — one/few signals, insufficient evidence.
- **EMERGING** — repeated directional signal.
- **VALIDATED** — repeated evidence across meaningful tests/context.
- **STALE / NEEDS RETEST** — historically useful but may no longer generalize.
- **REFUTED** — evidence materially contradicts the hypothesis.

Never label something validated because an AI thinks it sounds plausible.

## 12. Learning Promotion Rule
A raw metric does not become doctrine automatically.

Pipeline:
**Raw Event → Normalized Metric → Analysis → Learning Candidate → Confidence → Re-test → Validated Learning**

Even a validated marketing learning cannot override Product Truth or Brand Brain without Founder approval.

## 13. Weekly Learning Cycle
Each week:
1. freeze the measurement window;
2. validate data completeness;
3. normalize platform metrics;
4. score against each experiment's objective;
5. select Top 5;
6. diagnose why;
7. identify bottom/neutral experiments;
8. extract angle/hook/audience/format learnings;
9. propose next experiments;
10. nominate paid candidates;
11. write concise Founder report;
12. feed approved learnings into next week's strategy context.

## 14. Paid Amplification Memory
Principle:
**Organic discovers. Paid amplifies. Paid also learns.**

Top organic content is a candidate, not automatic ad spend.

Paid launch requires applicable Founder/budget gate.

Paid results must feed the same learning system so the engine can distinguish:
- organic resonance;
- paid reach;
- audience targeting effects;
- creative strength;
- conversion strength;
- fatigue.

## 15. Platform Normalization
Do not pretend TikTok, Instagram, Facebook and Threads metrics are identical.

Store native metrics first.
Create normalized analytical fields second.
Never discard source metrics.

Comparisons must account for:
- format;
- objective;
- audience;
- distribution;
- age of post;
- paid vs organic.

## 16. Attribution
Where technically possible, preserve:
**experiment → derivative → platform post → click/session → lead → conversion → paid campaign**

Where attribution is incomplete, label it incomplete. Never fabricate deterministic attribution.

## 17. Memory Freshness
Every learning should carry:
- first observed;
- last confirmed;
- number of supporting tests;
- contexts/platforms;
- confidence;
- next review/retest.

Fast-changing platform tactics should decay faster than durable customer pain insights.

## 18. Anti-Contamination Rules
Never write into Marketing Memory as fact:
- synthetic metrics;
- demo/test metrics mixed with production;
- fabricated testimonials;
- AI guesses;
- unverified competitor claims;
- private brainstorms labeled as customer evidence;
- paid results attributed to organic without evidence.

Separate:
**hypothesis / observation / evidence / validated learning / doctrine.**

## 19. Founder Corrections
Founder may:
- reject a learning interpretation;
- mark data contaminated;
- change strategic priority;
- approve a Brand Brain change;
- change scoring emphasis.

Do not delete raw evidence merely because strategy changes. Preserve history and version interpretation.

## 21. Founder Weekly Report
Minimum:
- experiments created;
- outputs by platform;
- failures;
- reach;
- retention/qualified engagement;
- qualified traffic;
- leads/conversions;
- Top 5;
- strongest/weakest angles;
- new learnings + confidence;
- paid results/spend;
- next tests;
- decisions requiring Founder approval.

Keep it concise; preserve detail in the underlying memory.

## 22. Initial State — 2026-09-04
**Performance memory is intentionally EMPTY.**

Known doctrine at initialization is not performance learning:
- four launch platforms: TikTok, Instagram, Facebook, Threads;
- 5 core experiments/day target;
- platform-native adaptation;
- approximately Top 5 weekly winner selection;
- qualified business signal > vanity views;
- paid amplification follows evidence and approval;
- n8n orchestrates;
- Product Truth and Brand Brain constrain generation.

These are operating rules, not claims that the market has validated them.

## 23. Definition of Done
Marketing Memory is solid when:
- every published output is traceable to a core experiment;
- raw metrics are preserved;
- platform metrics are not falsely equated;
- Top 5 can be reproduced from stored evidence;
- every learning has evidence/confidence/freshness;
- winners and losers both inform future strategy;
- paid and organic learning remain distinguishable;
- no synthetic data contaminates production learning;
- agents can retrieve relevant historical learning without treating hypotheses as facts;
- Product Truth and Brand Brain remain higher-order constraints.
