# CEFFLO — CONTENT PHILOSOPHY
**Status:** Canonical Marketing Knowledge SOT
**Version:** 1.0 — 2026-09-04
**Supersedes:** The old 3-core-content/day, 21/week volume doctrine.
**Preserves:** Useful situation, angle, hook, anti-duplication and truth principles from the earlier Content Engine.

## 1. North Star
Content exists to bring the right business from:
**doesn't know Cefflo → recognizes the problem → understands delivery as an operation → understands Cefflo → trusts → tries → uses → proves value → refers**

Desired eventual genuine user reaction:
> "Aku tak nak balik kepada cara lama."

Never manufacture that quote as a testimonial.

## 2. Current Volume Doctrine
Target:
**5 core experiments/day × 7 = ~35 core experiments/week**

Each core experiment may produce platform-native derivatives across three default lanes:
- Meta (Instagram + Facebook, one shared package by default);
- TikTok;
- Threads.

Instagram and Facebook may still be split into separate packages when a genuine platform-fit reason exists (`08_AI_CONTENT_ENGINE_ORCHESTRATOR.md` §10).

Theoretical ceiling:
**35 × 3 = ~105 outputs/week**

**Superseded 2026-09-10:** the previous figure of ~140 outputs/week assumed four independent platform lanes. Corrected per the Founder-approved Meta-shared-default model — see `docs/cefflo/05_DECISIONS.md` D-25.

105 is not a quota. Platform fit and quality override multiplication.

## 3. Content Is Experimentation
Every core item should test something:
- audience;
- pain;
- angle;
- hook;
- format;
- proof;
- CTA;
- platform execution.

Content without a hypothesis may still be published for genuine communication, but the engine should prefer traceable experiments.

## 4. Daily Portfolio
Do not force five identical content types.

Default portfolio can draw from:
1. Attention / Relatable;
2. Education / Authority;
3. Product / Demonstration;
4. Founder POV / Objection / Category scenario;
5. Proof / Conversion / experimental slot.

Exact mix is configurable by launch stage and Marketing Memory.

**Video-specific addendum:** for V1 short-form video specifically, `09_CONTENT_WORLD_PRODUCTION_DOCTRINE.md` §6 sets a target split of ~45% Problem→Product→Outcome, ~35% Product-led Proof, ~20% Education. This is a video-only refinement of the mix above, not a repo-wide override — non-video content (Threads text, static/carousel) remains governed by this section's general "configurable" framing.

## 8. Hook Doctrine
Families:
- direct pain;
- question;
- POV;
- contrarian;
- specific truthful number;
- pattern interrupt;
- before/after;
- operational observation;
- Founder lesson;
- myth;
- challenge;
- "what happens when…";
- "if this is you…";
- "stop doing…";
- "why…";
- "the real problem is…".

Rules:
- specific > generic;
- curiosity without deception;
- no fake urgency;
- no invented statistics;
- no generic AI clichés;
- first seconds/lines must earn attention.

**Language cross-reference:** for Malaysian Malay hooks/dialogue specifically, `10_BRAND_VOICE_LANGUAGE_SYSTEM.md` §12 (Hook Doctrine) and §21 (Language QA) govern native-generation and naturalness requirements — hooks must never be produced by translating an English master.

## 9. Don't Tell, Show
Product content should prefer:
**Problem → Product Evidence → Operational Meaning**

One product content item should normally make one operational transformation clear.

Show real UI/product when available. If using a prototype, make its status honest.

## 10. Education Rule
Not every post should sell Cefflo.

Teach:
- why local delivery becomes operationally difficult;
- service-area thinking;
- zones;
- planning;
- multi-drop principles;
- preparation/readiness;
- rider coordination;
- customer visibility;
- exception handling;
- scaling operational discipline.

Do not teach unverified Cefflo capabilities as if they are live.

## 11. Founder Content
Useful:
- product decisions;
- lessons;
- operational observations;
- why Cefflo rejects certain models;
- build decisions with customer relevance.

Avoid:
- turning the feed into a dev changelog;
- invented Founder history;
- motivational filler;
- exposing private people/details.

## 12. Proof Doctrine
Use proof only when real:
- product capture;
- genuine user reaction;
- consented testimonial;
- real workflow;
- real measured outcome;
- case study.

If proof does not exist, publish education/product evidence instead. Never fill the gap with synthetic social proof.

## 13. Anti-Duplication
Before generation check:
- same situation;
- same angle;
- same hook structure;
- same claim;
- same visual/format;
- recency;
- previous performance.

Allowed:
- same situation + new angle;
- winner + new hook;
- winner + new format;
- winner + native platform remake;
- strong old insight after cooldown.

Principle:
**Recycle insight. Don't recycle the post.**

## 14. Platform-Native Doctrine
### TikTok
Short-video bias, fast hook, scenario/POV, native pacing, captions.

### Instagram
Reels, carousel, static; stronger visual coherence; do not force every concept into Reel.

### Facebook
Reels/video/static/carousel plus useful business context.

### Threads
Text-native observation, lesson, contrarian thought, mini-story, discussion. Never paste an IG caption blindly.

## 16. Success Hierarchy
Ask:
> "Which content produced the most valuable business signal?"

Prioritize according to objective:
- conversion;
- qualified lead;
- trial/early access;
- qualified traffic;
- profile/site action;
- meaningful saves/shares/comments;
- retention/watch quality;
- views.

Do not reward vanity by default.

## 17. Launch-Stage Adaptation
Pre-launch: pain, education, Founder POV, truthful preview, early access.
Pilot: real workflows, reactions, learning, product evidence.
Launch: live demos, onboarding, current offer, objections, conversion.
Growth: real testimonials/case studies, winner remakes, referrals, paid amplification.

## 20. Definition of Done
The Content Engine can generate ~35 diverse weekly core experiments, adapt only where platform-native, preserve truth/voice, avoid duplication, capture hypotheses, and feed real performance into Marketing Memory.
