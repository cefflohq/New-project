Claude should:

-   inspect the actual baseline before editing;
-   follow Task MD phases and boundaries;
-   preserve product behavior unless change is authorized;

-   reconcile active legacy conflicts;
-   test actual changed behavior;
-   provide evidence;
-   keep unrelated changes out;

Do not turn a complete Master MD back into a series of unnecessary
planning questions.

Brand Brain wins for doctrine.

Actual repo/runtime wins for whether an implementation fact currently
exists.

------------------------------------------------------------------------

## 6. REPO AUDIT METHOD

For reconciliation tasks:

1.  discover relevant files/surfaces;
2.  search explicit legacy terms;
3.  inspect semantic conflicts, not only keywords;
4.  classify each meaningful conflict:
    -   KEEP
    -   UPDATE
    -   DEPRECATE
    -   ARCHIVE
    -   REMOVE
5.  change only what the Task MD authorizes;
6.  preserve useful historical evidence when appropriate;
7.  ensure current active docs/copy point to canonical truth.

Do not mass-delete based on a grep result.

------------------------------------------------------------------------

## 7. IMPLEMENTATION QUALITY

For substantial UI work: - use semantic tokens/shared primitives where
appropriate; - maintain Light/Dark structural parity; - follow current
UI/UX/CX doctrine; - remove legacy rendered styling systematically; - do
not fabricate backend functionality; - preserve accessibility and
responsive behavior.

For backend/product work: - preserve contracts and security
boundaries; - use migrations/RPC changes only when authorized; - verify
rather than assume.

------------------------------------------------------------------------

## 8. CONTEXT EFFICIENCY

Do not load every historical Cefflo MD by default.

Use: - Brand Brain; - Core OS; - Claude Operating; - current Task MD;

then retrieve only evidence required to execute.

Do not repeat a prior verified audit unless: - baseline changed; - Task
MD requires verification; - evidence is missing/stale.

------------------------------------------------------------------------

## 9. BRANCH / WORKTREE

Follow the Task MD exactly for: - baseline; - branch; - worktree; - file
ownership; - collision boundaries.

Report: - starting SHA; - final SHA; - branch; - working tree status.

Do not merge to Production without explicit Founder authorization.

------------------------------------------------------------------------

## 10. TESTING AND EVIDENCE

Report only what was actually run/verified.

For UI-visible work, include real browser/preview evidence when required
and technically available.

A generated screenshot is not proof of deployed runtime behavior unless
it came from that runtime.

If preview/deployment is blocked by external permissions, report
BLOCKED/PARTIAL and the exact required external action.

Do not bypass fail-closed environment/security guards merely to produce
a link.

------------------------------------------------------------------------

## 11. HANDOFF

When another agent may continue, provide a compact handoff containing:

-   task;
-   branch;
-   starting/final SHA;
-   implementation summary;
-   files changed;
-   tests;
-   known gaps;
-   blockers;
-   `DO NOT TOUCH`;
-   next permitted action;
-   Founder Gate status.

Do not require Founder to relay the whole conversation.

------------------------------------------------------------------------

## 12. STOP CONDITIONS

Stop when: - Founder decision is required; - Task MD defines a gate; -
Production authorization is required; - external permission blocks safe
execution; - continuing would require inventing secrets/config; - a
genuine source-of-truth conflict remains unresolved.

------------------------------------------------------------------------
